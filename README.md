# HSIわかる？

HSI（Horizontal Situation Indicator）の見方を、動かしながら学ぶ学習ツール。

> **STUDY ONLY / 学習専用**
> このアプリは学習専用です。実際の飛行、航法判断、訓練、試験、運航には使用できません。

Sky Apps 航空航法シリーズ第2弾（第1弾: VORわかる？）。

## 目的

HSIは部品名を暗記する計器ではありません。
このアプリは「パイロットがコックピットで計器を見て、何を判断しているか」を、
初心者が自分で動かしながら理解できるようにします。

| シリーズ | 問い |
|---|---|
| VORわかる？ | 自分は**どこにいる**のか？ |
| HSIわかる？ | 自分は**どちらを向いていて**、**どちらへ進むべき**か？ |

## 設計上の約束（変更しない）

1. **自機シンボルは上向き固定** — 回転レイヤの外に置く
2. **Heading変化ではコンパスローズが回る** — 回転の源は `-heading` ひとつだけ
3. **CourseはHeadingと独立** — heading操作でcourseを書き換えない
4. **CDIの判定にheadingを使わない** — VORわかる？から引き継ぐ原則
5. **判定値は1か所でのみ導出する** — `deriveHsiState()` 以外で状態を作らない
6. **問題の正解を直書きしない** — 判定ロジックの算出値から組み立て、テストで一致を担保する
7. **実機の完全コピーはしない** — 概念のみ参照し、意匠は独自に作る

## Lesson構成（全5レッスン）

| # | タイトル | ねらい | 上空図 |
|---|---|---|---|
| 1 | HSIって何？ | 自機は固定、ローズが回る。Headingの意味 | − |
| 2 | HeadingとCourse | 2つは別物だと体験で理解する | − |
| 3 | VORのCDIをHSIで読む | VORで見たCDIがHeadingと一緒に表示される | ● |
| 4 | Intercept | コースへ近づき、捕まえる。中央＝終了ではない | ● |
| 5 | Tracking | 風があるとHeadingとTrackが違う（概念のみ） | ● |

Lesson 1・2 は情報量を絞るため上空図を出しません。上空図はLesson 3から登場します。
Lesson 4 は「CDIが右なら右」の方向暗記にならないよう、上空図とHSI表示の対応から判断させます。

### 上空図の扱い

上空図は**理解の補助と答え合わせ**です。答えを先に見せる道具にはしません。

- 説明・まとめの手順では出す（計器の見え方と位置関係を対応づける）
- 確認問題では出さない。**答えたあとにだけ**出す（`revealVisible`）

出題中に上空図があると、計器を読まずに図から答えられてしまうためです。
この決まりは `lesson3.test.ts` で固定しています。

Lesson 4 は狙いが違うため、**全手順で上空図と計器を同時に出します**。
「計器を読む」練習ではなく「図と計器を重ねて状況を判断する」練習だからです。
代わりに、答えがそのまま書いてある状況表示（SITUATION）を確認問題では出しません。

### Lesson 4 が方向暗記にならないための決まり

「CDIが左だから左へ曲がる」で終わる教材にしないため、次の4点を守ります。

1. 全手順で上空図と計器を同時に出す。片方だけを見て答えられる手順を作らない
2. **同じ位置・同じCDI表示のまま機首だけを変えた3つを並べる**。
   近づく／変わらない／離れる、の3通りに分かれることを1画面で見せる
3. 確認問題は「CDIはどちらか」ではなく「いま近づいているか」を問う。
   この答えはCDIの左右だけからは決まらない
4. CDIが中央で終わりにしない。捕まえたあとコースへ機首を合わせ、Lesson 5 へつなぐ

`interceptTrend` はCDIの符号ではなく、対地進路とコース線の関係から導出します。
これらは `lesson4.test.ts` で固定しています。

各レッスンは次の手順種別を組み合わせたデータとして定義します
（画面側にレッスン固有の分岐を持たせない設計）。

- `teach` … 説明（用語カードつき）
- `interact` … 自分で動かして計器の変化を確かめる。条件を満たすまで次へ進まない
- `compare` … 複数の状態を並べて見くらべる
- `quiz` … 選択式の確認問題。間違えるたびに手がかりを1つずつ増やす
- `summary` … まとめ

`interact` を終える条件は3通りあります。
指定した角度ぶん動かす／近づく状態を作る（`requiredTrend`）／
機首をコースへ合わせる（`requiredCourseAlignmentDeg`）。

学習記録は端末内の `localStorage`（キー: `hsiWakaru.progress.v1`）に保存します。
保存するのは各レッスンの状態・再開位置・完了日時だけで、回答内容や正解数は保存しません。

## 計器の層構造

この入れ子が実装の核心です。実機の考え方をそのまま形にしてあります。

```
固定層（絶対に回さない）
  ├ ラバーライン（機首指標）
  └ 自機シンボル（常に上向き）
回転層1  rotate(-heading)   コンパスローズ
  └ 回転層2  rotate(course) コース矢印・CDI・TO/FROM（一体で回る）
```

回転層2を回転層1の内側に置いているため、

- Heading を変えるとローズごとコース矢印も回る
- Course を変えるとコース矢印とCDIだけが回る

が、条件分岐なしに構造から出てきます。

回転角は `continuousAngle()` で連続値に展開してから渡します。
359°→360° のときに359度ぶん逆回転しないようにするためで、この値は表示専用です。

## 技術構成

| 種別 | 内容 |
|---|---|
| UI | React 19 / TypeScript |
| ビルド | Vite |
| テスト | Vitest |
| Lint | oxlint |
| ルーティング | ハッシュベースの自作ルーター（ライブラリ非依存） |
| 状態管理 | React のみ（外部ライブラリ・Contextなし） |
| スタイル | 素のCSS + カスタムプロパティ（Sky Apps Design System v1.0 準拠） |
| 描画 | インラインSVG |
| アニメーション | CSS transition のみ（`prefers-reduced-motion` で無効化） |
| 解析 | @vercel/analytics |
| 配信 | Vercel |

バックエンド、ログイン、外部データベース、GPSはありません。
外部への送信は行いません（書体の読み込みのみ Google Fonts を利用）。

主なディレクトリ：

```
src/
  domain/hsi/   HSI判定ロジック（角度・座標・状態導出・風）— UIに依存しない純粋関数
  lessons/      レッスン定義データ、採点、再開位置
  components/   計器・上空図・スライダーなどの表示部品
  pages/        画面
  app/          ルーター、状態フック
  storage/      学習記録の保存
  styles/       デザイントークンと共通スタイル
```

## ローカルでの起動方法

Node.js が必要です。

```bash
npm install
npm run dev
```

起動後 http://localhost:5174 を開きます（VORわかる？の5173と衝突しないよう分けています）。

スマホ実機で確認する場合：

```bash
npm run dev -- --host
```

その他のコマンド：

```bash
npm run build      # 型チェック + 本番ビルド
npm run preview    # ビルド結果をローカル確認
npm test           # ユニットテスト
npm run typecheck  # 型チェックのみ
npm run lint       # oxlint
```

## 免責

- このアプリはHSIの基本的な考え方を視覚的に学ぶための**学習ツール**です。
  実際の飛行、航法判断、訓練、試験、運航には使用できません。
- 表示は概念理解のために簡略化しています。実際の機器、公式資料、訓練機関の教材、
  および教官の指示を優先してください。
- 特定の機種・製品の再現ではありません。HSIに共通する考え方のみを取り入れ、意匠は独自に作成しています。
- 実在するVOR局・空港・航空路、実際の航空図は使用していません。
